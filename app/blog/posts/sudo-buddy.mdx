# SudoBuddy

SudoBuddy is an embedded TinyML assistant that lets you verify a handwritten Sudoku puzzle in real time — no phone, no screen, no cloud connection. Point the camera at the grid, say "check," and the system tells you whether your solution is valid.

Personal project built Nov–Dec 2025, running entirely on an **Arduino XIAO microcontroller**.

## Results

- **95–99% digit recognition accuracy** under varied real-world lighting conditions
- **Sub-100ms inference latency** on embedded hardware with no GPU
- **4× model size reduction** via quantization — from full-precision to INT8 — while preserving accuracy
- Fully hands-free: no screen, no keyboard, no external display required

## How It Works

### Voice Control (KWS)

A lightweight keyword-spotting model listens for two commands:

- **"Start"** — captures the Sudoku grid and initializes the board state
- **"Check"** — validates the current solution against Sudoku constraints

This keeps the user's hands free and attention on the paper puzzle, not a device.

### Board Capture & Digit Recognition

On a "start" command, the system:

1. Captures the grid through an embedded camera
2. Normalizes lighting and corrects orientation
3. Segments the board into 81 individual cells
4. Classifies each digit using a custom CNN running fully on-device

### Solution Validation

After classification, each row, column, and 3×3 subgrid is checked for conflicts. The board returns one of three states: valid solution, partial but consistent, or invalid configuration. LED feedback communicates the result without any screen.

## Technical Challenges

Getting 95–99% accuracy within the memory and compute budget of an Arduino XIAO required careful co-design of the model and the preprocessing pipeline. The main constraints:

- Flash and RAM limits ruled out any off-the-shelf vision model
- Quantization (full-precision → INT8) reduced model size by 4× but required retraining to recover accuracy
- Preprocessing had to be fast enough to not blow the latency budget before inference even started
- Lighting variability in handwritten digit images is harder than MNIST-style benchmarks

## Tech Stack

**Model Training**
- PyTorch for CNN and keyword-spotting model development
- Python for dataset preparation, training, and evaluation

**Deployment**
- TensorFlow Lite Micro for on-device INT8 inference
- C++ for embedded runtime and preprocessing pipeline
- Quantization-aware training to preserve accuracy after INT8 conversion

**Hardware**
- Arduino XIAO microcontroller
- Embedded camera module
- LED array for visual feedback
